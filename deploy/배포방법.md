# 배포 방법 — Oracle Cloud 무료 티어

집 PC 에서만 보이던 화면을 인터넷 주소로 여는 절차다. 한 번만 하면 된다.

**전체 소요: 1시간 30분쯤.** 대부분은 Oracle 가입 심사를 기다리는 시간이다.

> 이 문서의 명령은 **서버에 접속한 상태**에서 실행한다. 집 PC 에서 실행하는 것은
> "집 PC 에서" 라고 따로 적어 둔다.

---

## 미리 알아 둘 것 두 가지

**1. 이 방식은 HTTPS 가 아니다.**
도메인 없이 IP 로 접속하므로 브라우저 주소창에 "안전하지 않음" 이 뜬다.
접근 비밀번호가 암호화되지 않은 채 오간다는 뜻이다. 읽기 전용 대시보드라 피해는 제한적이지만,
공용 와이파이에서는 비밀번호가 노출될 수 있다.
나중에 도메인을 사면 `deploy/Caddyfile` 주석의 HTTPS 블록으로 바꾸는 것만으로 해결된다.

**2. Oracle 무료 인스턴스는 만들 때 "용량 부족" 이 자주 난다.**
무료라서 인기가 많아 그렇다. 실패하면 며칠 뒤에 다시 시도하거나, 다른 가용 도메인(AD)을 골라 본다.
계속 막히면 알려 달라 — 유료 VPS(월 $5~6)로 방향을 바꾸는 편이 시간을 아낀다.

## 1단계 — Oracle Cloud 가입 (20분, 심사 대기 별도)

1. **https://www.oracle.com/kr/cloud/free/** 접속 → **무료로 시작하기**
2. 국가 **대한민국**, 이메일 입력 → 인증 메일 확인
3. 계정 정보 입력. **홈 리전은 반드시 `South Korea Central (Seoul)` 또는 `South Korea North (Chuncheon)`** 로 고른다.
   ※ 홈 리전은 **나중에 바꿀 수 없다.** 한국 리전이어야 국내 API 응답이 빠르다.
4. 신용카드 등록 (본인 확인용이다. 무료 티어만 쓰면 청구되지 않는다)
5. 가입 완료 후 **"평가판 업그레이드" 안내가 떠도 누르지 않는다.** 무료 티어 그대로 쓴다.

---

## 2단계 — 서버 만들기 (15분)

1. 로그인 후 좌측 햄버거 메뉴 **☰ → 컴퓨트 → 인스턴스**
2. **인스턴스 생성** 클릭
3. 이렇게 설정한다:

| 항목 | 값 |
| --- | --- |
| 이름 | `stock` (아무거나) |
| 이미지 | **Canonical Ubuntu 24.04** |
| 형상(Shape) | **VM.Standard.A1.Flex** (ARM) — OCPU **1**, 메모리 **6GB** |
| 네트워크 | 기본값 그대로 (VCN 자동 생성) |
| 공용 IP 할당 | **예** |

   ※ A1.Flex 가 "용량 부족" 이면 **VM.Standard.E2.1.Micro** 를 고른다. 메모리가 1GB 라
   느리지만 동작한다(아래 4단계에서 스왑을 만들어 보완한다).

4. **SSH 키 추가** 항목에서 **전용 키 저장** 을 눌러 키 파일(`.key`)을 내려받는다.
   ※ 이 파일이 서버에 들어가는 열쇠다. 잃어버리면 접속할 수 없다. 안전한 곳에 둔다.
5. **생성** 클릭 → 몇 분 뒤 상태가 **실행 중** 이 되면 **공용 IP 주소** 를 적어 둔다.

---

## 3단계 — IP 를 고정으로 바꾸기 ⚠️ 반드시 한다 (5분)

기본으로 주는 공용 IP 는 **임시(ephemeral)** 라서 서버를 재시작하면 바뀔 수 있다.
IP 가 바뀌면 토스증권 API 가 403 으로 막히고 접속 주소도 달라진다.

1. 인스턴스 상세 화면 → 아래로 스크롤 → **연결된 VNIC** → VNIC 이름 클릭
2. **IPv4 주소** → 오른쪽 점 세 개 **⋮** → **편집**
3. **공용 IP** 항목에서 **예약된 공용 IP** 선택 → **새 예약된 IP 생성** → 이름 아무거나 → **업데이트**
4. 잠시 뒤 새 IP 가 나온다. **이 IP 를 적어 둔다.** 앞으로 이것이 서버 주소다.

## 4단계 — 서버 접속 (10분)

**집 PC 에서** PowerShell 을 열고:

```powershell
# 내려받은 키 파일 경로로 바꾼다
cd $HOME\Downloads
# 키 파일 권한을 잠근다 (이걸 안 하면 접속이 거부된다)
icacls .\ssh-key-2026-08-11.key /inheritance:r /grant:r "$($env:USERNAME):(R)"

# 접속 (IP 는 3단계에서 적어 둔 것)
ssh -i .\ssh-key-2026-08-11.key ubuntu@서버IP
```

처음 접속하면 `Are you sure you want to continue connecting?` 이 뜬다. `yes` 입력.

접속되면 프롬프트가 `ubuntu@stock:~$` 로 바뀐다. **여기서부터는 서버 안이다.**

### 스왑 만들기 (메모리 1GB 형상을 골랐다면 필수, 아니면 건너뛰어도 됨)

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## 5단계 — 방화벽 열기 ⚠️ Oracle 은 두 군데를 열어야 한다 (10분)

이 단계를 빠뜨리면 "접속이 안 되는데 서버는 멀쩡한" 상황이 된다. Oracle 만의 함정이다.

### 5-1. 클라우드 쪽 (웹 화면에서)

1. 인스턴스 상세 → **가상 클라우드 네트워크** 링크 클릭
2. 좌측 **보안 목록** → 기본 목록 클릭
3. **수신 규칙 추가**:

| 항목 | 값 |
| --- | --- |
| 소스 CIDR | `0.0.0.0/0` |
| IP 프로토콜 | TCP |
| 대상 포트 범위 | `80` |

### 5-2. 서버 쪽 (SSH 접속한 터미널에서)

우분투 이미지에는 자체 방화벽 규칙이 들어 있다. 이것도 열어야 한다.

```bash
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo netfilter-persistent save
```

## 6단계 — 프로그램 설치 (10분)

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3.12-venv git curl

# Node.js 22 (화면 빌드에 필요)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# Caddy (비밀번호·웹 서버)
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy

# 확인 — 셋 다 버전이 나오면 성공
python3 --version && node --version && caddy version
```

## 7단계 — 코드 올리기 (10분)

먼저 **집 PC 에서** GitHub 에 코드를 올려야 한다. (아직 안 했다면 클로드 코드에게 요청한다.)

서버에서:

```bash
# 전용 사용자를 만든다. 웹 서비스를 관리자 권한으로 돌리지 않기 위해서다.
sudo useradd -m -s /bin/bash stock
sudo mkdir -p /opt/stock && sudo chown stock:stock /opt/stock

# stock 사용자로 전환해 코드를 받는다
sudo -u stock -H bash
cd /opt/stock
git clone https://github.com/사용자이름/저장소이름.git .

# 파이썬 환경
python3 -m venv .venv
.venv/bin/pip install -q -r backend/requirements.txt

# 화면 빌드
cd frontend && npm ci && npm run build && cd ..

mkdir -p data
exit    # stock 사용자에서 빠져나온다
```

## 8단계 — 키 파일(.env) 만들기 (10분)

`.env` 는 Git 에 올라가지 않으므로 서버에서 직접 만든다.

```bash
sudo -u stock nano /opt/stock/.env
```

**집 PC 의 `.env` 파일을 메모장으로 열어 내용을 통째로 복사**한 뒤,
터미널 창에서 **마우스 오른쪽 클릭**으로 붙여넣는다.

붙여넣은 뒤 아래 한 줄만 고친다:

```
APP_ENV=production
```

저장: `Ctrl+O` → `Enter` → `Ctrl+X`

권한을 잠근다 (다른 사용자가 못 읽게):

```bash
sudo chmod 600 /opt/stock/.env
sudo chown stock:stock /opt/stock/.env
```

## 9단계 — 서비스 등록 (5분)

```bash
sudo cp /opt/stock/deploy/stock-dashboard.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now stock-dashboard

# 확인 — active (running) 이 나와야 한다
sudo systemctl status stock-dashboard --no-pager

# 응답 확인 — {"status":"ok"} 가 나와야 한다
curl http://127.0.0.1:8000/health
```

`active (running)` 이 아니면:

```bash
sudo journalctl -u stock-dashboard -n 50 --no-pager
```

## 10단계 — 비밀번호 설정과 Caddy (10분)

```bash
# 비밀번호 해시를 만든다. 원하는 비밀번호를 두 번 입력한다.
caddy hash-password
```

`$2a$14$...` 로 시작하는 긴 문자열이 나온다. **복사한다.**

```bash
sudo cp /opt/stock/deploy/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile
```

`여기에_해시를_붙여넣는다` 부분을 방금 복사한 해시로 바꾼다.
(`$2a$14$` 부터 끝까지 전체를 붙여넣는다.)

저장: `Ctrl+O` → `Enter` → `Ctrl+X`

```bash
sudo systemctl reload caddy
sudo systemctl status caddy --no-pager
```

## 11단계 — 토스증권 허용 IP 등록 ⚠️ 빠뜨리면 시세가 안 나온다 (2분)

**집 PC 에서** 브라우저로:

1. **tossinvest.com** 로그인 → **설정 → Open API → 허용 IP 관리**
2. **3단계에서 적어 둔 서버 IP** 를 추가한다
3. 집 IP 도 그대로 둔다 (집에서 개발할 때 필요하다)

---

## 12단계 — 접속 확인

브라우저에서:

```
http://서버IP
```

1. 아이디/비밀번호를 묻는 창이 뜬다 → 아이디 `view`, 비밀번호는 10단계에서 정한 것
2. 대시보드가 나오면 성공이다

## 문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| 브라우저가 아예 안 열림 | 5단계 방화벽 **두 군데** 를 다 열었는지 |
| 비밀번호 창은 뜨는데 그 뒤 오류 | `sudo systemctl status stock-dashboard` |
| 화면은 뜨는데 시세가 비어 있음 | 11단계 허용 IP 등록, 그리고 `sudo journalctl -u stock-dashboard -n 50` |
| 시세가 403 오류 | 서버 IP 가 바뀌었을 수 있다. 3단계에서 **예약된 IP** 로 바꿨는지 확인 |
| 화면 빌드 중 멈춤 | 메모리 부족이다. 4단계 스왑을 만든다 |

로그 실시간 보기:

```bash
sudo journalctl -u stock-dashboard -f
```
