# UX 작업 계획

화면을 남에게 보여줄 물건으로 만드는 작업. **한 단계씩, 눈으로 확인하고 넘어간다.**

이 문서를 만든 이유: 0·1단계를 하면서 세운 계획이 대화창에만 있었고 저장되지 않았다.
커밋 메시지가 "2·4단계에서 그 파일을 재구성한다"고 미루어 둔 것들이 있는데 그 목록이
어디에도 없었다. 다시 세워 여기 남긴다.

최종 갱신: 2026-08-31

---

## 원칙 — 0·1단계에서 지켜서 효과를 본 것

- **파일을 열 때 그 파일만 이행한다.** 곧 재구성할 파일을 미리 손대지 않는다. 두 번 고치게 된다.
- **눈으로 확인하고 커밋한다.** 브라우저에서 실제로 눌러 보고, 무엇을 눌러 무엇을 봤는지 커밋 메시지에 적는다.
- **테스트 340개를 깨지 않는다.** 화면 작업이라도 예외가 아니다.
- **전후 스크린샷을 `docs/screenshots/` 에 남긴다.** 나중에 무엇이 나아졌는지 말로 설명할 필요가 없어진다.

---

## ✅ 0단계 — 타이포그래피와 명암비 (2026-08-27 완료)

폰트 고정(Pretendard 셀프호스팅) · 글자 크기 스케일 한 칸 상향 · WCAG AA 미달 회색 173곳 ·
상승/하락 색 명도 맞춤 · 우측 패널이 눌리던 그리드 버그.

## ✅ 1단계 — 프리미티브와 표 (2026-08-27 완료)

`components/ui/` 에 `Card` · `Segmented` · `Status` · `Metric` · `DataTable` 을 만들고
복붙된 마크업을 옮겼다. 곁가지로 접근성이 크게 붙었다 — 표를 키보드로 조작할 수 있게 됐고
(`<tr onClick>` 0개), 정렬 머리글이 진짜 버튼이 됐고, `aria-sort`·`aria-pressed`·`role="alert"` 이 생겼다.

**남겨 둔 것**: 카드 껍데기를 직접 그리는 곳이 12개 파일에 남았다. 전부 아래 2·4단계에서
어차피 다시 여는 파일이라 미뤘다.

---

## 2단계 — 종목 상세 재구성 ← **다음**

### 무엇이 문제인가

종목 상세는 이 앱에서 가장 오래 머무는 화면인데, **420px 짜리 세로 기둥에 카드 11개가
쌓여 있다.**

```
현재가 · 확정종가 → 차트 → 시가·고가·저가·거래량 → 수급 → 메모
→ 밸류에이션 → 동종업계 → 재무 → 사업보고서 분석 → 공시
```

관찰된 증상 세 가지:

1. **목록과 상세가 한 몸으로 스크롤한다.** 목록이 50줄이라, 상세의 재무를 보려고 내리면
   목록은 이미 40번째 종목을 지나 있다. 다른 종목을 눌러 비교하려면 다시 맨 위로 올라와야 한다.
2. **표가 기둥보다 넓다.** 동종업계 표는 `min-w-[520px]` 인데 기둥이 420px 이라 항상 가로로
   잘린다. `07-kr-detail-after-primitives.png` 에서 매출 열이 화면 밖으로 나가 있다.
3. **11개 카드가 각자 로딩한다.** 종목을 바꾸면 카드마다 따로 "불러오는 중"이 떴다가
   내용이 들어오면서 아래 것들을 밀어낸다. 화면 전체가 몇 초간 출렁인다.

### 할 일

- **상세를 섹션으로 나눈다.** `개요 / 재무 / 공시·분석` 세 묶음. 첫 화면(개요)에 현재가·차트·
  시세·수급·메모가 들어가고, 나머지는 눌러서 연다. 지금은 배당수익률을 보려고 차트를
  세 번 지나쳐야 한다.
- **상세 기둥을 `sticky` 로 고정한다.** 목록을 훑으면서 상세를 계속 볼 수 있게 한다.
  높이가 화면을 넘으면 기둥 안에서만 스크롤한다.
- **폭이 필요한 것은 폭을 준다.** 동종업계·재무 표는 기둥에 욱여넣는 대신 넓은 자리로 옮기거나,
  좁은 폭에 맞는 열만 남기고 나머지는 접는다. 지금처럼 "있는데 안 보이는" 상태로 두지 않는다.
- **로딩을 한 번으로 모은다.** 카드마다 따로 깜빡이지 않게, 자리를 미리 잡아 두고
  (skeleton) 채운다.
- 이 파일들을 열면서 **남은 카드 껍데기를 `Card` 로 이행한다** — `StockDetailPanel`,
  `UsDetailPanel`, `PriceChart`, `StockNotes`, `TenKAnalysis`, `ReportAnalysis`.

### 국내와 미국을 같이 고친다

`StockDetailPanel`(국내)과 `UsDetailPanel`(미국)은 담기는 값이 달라 파일을 나눠 두었지만
**구조는 같아야 한다.** 한쪽만 고치면 탭을 옮길 때마다 다른 규칙을 익혀야 한다.

### 확인 방법

브라우저에서 — 종목을 세 개 연달아 눌러 상세가 따라오는지, 목록을 끝까지 내려도 상세가
보이는지, 동종업계 표가 잘리지 않는지, 종목을 바꿀 때 화면이 출렁이지 않는지.

## 3단계 — 포커스와 화면 읽기

1단계에서 표는 키보드로 열렸지만 **나머지가 남았다.**

### 무엇이 문제인가

- **포커스 표시가 아예 없다.** `index.css` 에 focus 스타일이 한 줄도 없고, 검색창·메모장 등
  7곳은 `outline-none` 으로 브라우저 기본 표시마저 지운 뒤 테두리 색만 아주 조금 바꾼다.
  키보드로 쓰면 **지금 어디에 있는지 알 수 없다.**
- **탭이 탭이 아니다.** 국내·미국·관심·분석·일정은 그냥 `<button>` 다섯 개다. `role="tab"` 도
  ←→ 이동도 없다. 1단계에서 표에 붙인 규칙과 어긋난다.
- 검색 결과가 몇 건인지, 필터를 눌러 목록이 바뀌었는지가 **소리로 전달되지 않는다**(`aria-live`).

### 할 일

- 포커스 링을 토큰 하나로 정하고 전역에 적용한다. `outline-none` 7곳을 걷어낸다.
- 탭 묶음을 `role="tablist"` 로 만들고 ←→·Home/End 를 붙인다.
- 목록 갱신을 `aria-live="polite"` 로 알린다.
- 키보드만으로 앱을 한 바퀴 돈다 — 검색 → 정렬 → 종목 선택 → 상세 섹션 이동 → 메모 저장.

## 4단계 — 일정·분석 화면 정리

지금까지 손대지 않은 두 화면. **여기서 남은 카드 껍데기 이행이 끝난다.**

### 일정(캘린더) — 425줄, 가장 큰 화면 파일

달력 격자·목록·필터가 한 파일에 있고 카드를 직접 그린다. 쪼개고 `Card`·`Segmented` 로 옮긴다.
달력은 격자 자체가 접근성이 까다롭다 — 날짜 칸을 키보드로 옮길 수 있어야 한다.

### 분석(스크리너)

- 조건 입력이 `<input type=number>` 5개 + `<select>` 인데 **라벨이 11px 이다.** 0단계에서
  "읽어야 하는 문장은 13px 이상, 11px 은 분류 배지에만"이라고 정해 놓고 여기만 예외로 남았다.
- 프리셋 버튼 4개가 `Segmented` 가 아니라 각자 그린 버튼이다. 무엇이 눌려 있는지 표시가 없다.
- 조건을 바꿨을 때 **몇 개가 걸러졌는지**가 눈에 잘 안 띈다. 이 화면의 요점인데.

---

## 5단계 — 좁은 화면

**지금 이 앱은 노트북 이상에서만 쓸 수 있다.** 화면 폭에 따라 무언가를 감추거나 바꾸는
코드가 저장소에 0곳이다. 좁은 화면에서는 `lg:` 그리드가 풀려 목록 아래로 상세가 내려가고,
표는 `min-w-[720px]` 라 가로로 밀어야 한다.

포트폴리오 링크를 휴대폰으로 열어 볼 사람이 있다면 필요하다. **다만 이건 "안 하면 망가지는"
것이 아니라 범위를 넓히는 일이다** — 2·3·4단계를 마친 뒤 판단한다.

---

## 결정이 필요한 것 — 주소(URL)

지금 앱에는 **주소가 하나뿐이다.** 어느 탭을 보고 있는지, 어느 종목을 열었는지가 주소에
남지 않는다. 그래서:

- 특정 종목 화면을 **링크로 보낼 수 없다.** 포트폴리오로 공개할 때 "삼성전자 화면을 보세요"가 안 된다.
- 새로고침하면 국내 탭 첫 종목으로 돌아간다.
- 브라우저 뒤로가기가 앱을 벗어난다.

고치려면 라우터(주소와 화면을 연결하는 라이브러리)를 하나 들이거나, 직접 짧게 구현해야 한다.
**새 라이브러리는 확인을 받고 넣는 규칙**이라 여기 적어 둔다. 2단계에서 상세를 재구성할 때
같이 하는 것이 자연스럽다 — 그때 상세의 섹션 구분이 생기므로 주소에 담을 것이 정해진다.
