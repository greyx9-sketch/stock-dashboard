# UX 작업 계획

화면을 남에게 보여줄 물건으로 만드는 작업. **한 단계씩, 눈으로 확인하고 넘어간다.**

이 문서를 만든 이유: 0·1단계를 하면서 세운 계획이 대화창에만 있었고 저장되지 않았다.
커밋 메시지가 "2·4단계에서 그 파일을 재구성한다"고 미루어 둔 것들이 있는데 그 목록이
어디에도 없었다. 다시 세워 여기 남긴다.

최종 갱신: 2026-08-31

---

## 원칙 — 0·1단계에서 지켜서 효과를 본 것

- **파일을 열 때 그 파일만 이행한다.** 곧 재구성할 파일을 미리 손대지 않는다. 두 번 고치게 된다.
- **눈으로 확인하고 커밋한다.** 브라우저에서 실제로 눌러 보고, 무엇을 눌러 무엇을 봤는지 커밋 메시지에 적는다.
- **테스트 340개를 깨지 않는다.** 화면 작업이라도 예외가 아니다.
- **전후 스크린샷을 `docs/screenshots/` 에 남긴다.** 나중에 무엇이 나아졌는지 말로 설명할 필요가 없어진다.

---

## ✅ 0단계 — 타이포그래피와 명암비 (2026-08-27 완료)

폰트 고정(Pretendard 셀프호스팅) · 글자 크기 스케일 한 칸 상향 · WCAG AA 미달 회색 173곳 ·
상승/하락 색 명도 맞춤 · 우측 패널이 눌리던 그리드 버그.

## ✅ 1단계 — 프리미티브와 표 (2026-08-27 완료)

`components/ui/` 에 `Card` · `Segmented` · `Status` · `Metric` · `DataTable` 을 만들고
복붙된 마크업을 옮겼다. 곁가지로 접근성이 크게 붙었다 — 표를 키보드로 조작할 수 있게 됐고
(`<tr onClick>` 0개), 정렬 머리글이 진짜 버튼이 됐고, `aria-sort`·`aria-pressed`·`role="alert"` 이 생겼다.

**남겨 둔 것**: 카드 껍데기를 직접 그리는 곳이 12개 파일에 남았다. 전부 아래 2·4단계에서
어차피 다시 여는 파일이라 미뤘다.

---

## ✅ 2단계 — 종목 상세 재구성 (2026-08-31 완료)

420px 기둥에 카드 11개가 쌓여 있던 화면을 고쳤다. 넷을 한꺼번에 손댔다.

**섹션으로 나눴다.** `개요 / 재무 / 공시·분석`. 종목 이름과 현재가는 섹션 밖에 두어
어느 묶음을 보든 지금 얼마인지는 늘 보인다. 배당수익률을 보려고 차트를 세 번 지나칠
일이 없어졌다. 미국도 같은 뼈대다 — 미국 개요에는 차트·수급이 없는 대신 SEC 기업 정보
(업종·거래소·결산월·CIK·홈페이지)를 새 카드로 넣었다. 지금까지 화면에 없던 값이다.

**기둥을 화면에 붙잡아 뒀다**(`sticky`). 목록을 40번째 종목까지 내려도 상세는 그 자리에
있다. 상세가 화면보다 길면 기둥 안에서만 스크롤한다.

**표에 폭을 줬다.** 기둥을 480(lg)·560(xl)으로 넓히고, 동종업계 표의 최소 폭을
520 → 460 으로 내려 양쪽에서 만나게 했다. 넓힌 만큼 목록에 폭이 12px 모자라 잘리길래
`DataTable` 의 칸 좌우 여백을 12 → 10px 로 줄였다(글자 크기는 안 건드렸다 — 0단계에서
올려 둔 것이다). 1440px 에서 **두 표 모두 가로 스크롤 0** 이 됐다.

**로딩 자리를 미리 잡았다.** `ui/Skeleton` 을 만들고 열한 곳의 "불러오는 중…" 한 줄을
회색 막대로 바꿨다. 종목을 바꿔도 카드가 솟아오르며 아래를 밀어내지 않는다.
목록이 이미 아는 종목명을 상세에 넘겨(`name` prop) 제목은 아예 깜빡이지 않는다.

**주소가 생겼다** — 아래 "결정이 필요한 것"이 여기서 정리됐다. 라이브러리 없이
`lib/useRoute.ts` 하나로 끝냈다(번들 증가 0KB). 해시(`#/kr/005930/finance`)를 쓰므로
배포 서버 설정을 건드리지 않아도 새로고침이 된다.

  - 탭·섹션 전환은 뒤로가기 지점을 남기고(push), 종목 선택은 남기지 않는다(replace)
    — 표에서 ↑↓ 로 훑으면 한 칸마다 종목이 바뀌어서 뒤로가기가 못 쓰게 된다.
  - 주소에 적힌 종목은 목록 밖이어도 그대로 연다. 링크를 받고 들어온 종목이
    "상위 50위 밖"이라는 이유로 다른 회사로 튕기면 안 된다.
  - 분석(스크리너) 탭은 아직 주소를 쓰지 않는다. 4단계에서 그 파일을 열 때 붙인다.

**곁가지로 남은 카드 껍데기 이행이 끝났다** — 상세의 현재가·확정 종가·시세·기업 정보·
공시 카드가 전부 `Card` 로 갔다. 남은 곳은 4단계 파일(일정·분석·관심)뿐이다.

확인한 것 — 종목 세 개를 연달아 눌러 상세가 따라오는 것, 목록을 끝까지 내려도 상세가
보이는 것(`09-kr-finance-sticky.png`), 동종업계 표가 시총 열까지 다 보이는 것,
`#/kr/000990` 로 목록 밖 종목이 열리는 것, 뒤로가기가 앞 화면으로 돌아가는 것,
느린 SEC 응답에서 회색 막대가 자리를 지키는 것(`11-loading-skeleton.png`).
테스트 340개 그대로 통과.

## ✅ 3단계 — 포커스와 화면 읽기 (2026-08-31 완료)

1단계에서 표를 키보드로 열어 두고도 **정작 포커스가 보이지 않아 반쪽이었다.** 그것을 마처 묶었다.

**포커스 링을 전역에 깔았다.** `index.css` 에 focus 규칙이 한 줄도 없었고,
입력칸 일곱 곳은 `outline-none` 으로 브라우저 기본 표시마저 지우고 있었다.
0단계에서 만들어 두고 안 뎌 5 `--color-ring` 토큰을 이제 여기서 쓴다.
`:focus-visible` 이라 마우스로 누를 때는 링이 안 뜼고 키보드로 옆기면만 뜼다 —
마우스로 쓰는 화면은 전과 똑같다. 표의 행·입력칸은 링을 안쪽에 그려 옆 칸이나
카드 테두리에 잘리지 않게 했다.

**탭이 진짜 탭이 됐다.** 상단의 국내/미국/관심/분석/일정과, 2단계에서 만든
상세의 개요/재무/공시·분석 — 둘 다 `role="tablist"` 이고 ←→·Home/End 로 옥긴다.
묶음 전체가 탭 정지 하나다(roving tabindex) — 탭이 다섯 개라고 Tab 을 다섯 번
누르게 하지 않는다. 패널에는 `role="tabpanel"` 과 `aria-labelledby` 를 붙였다.

→ **화살표는 포커스만 옥기고 고르지는 않는다**(수동 활성화). 열 때마다 DART·SEC 를
부르기 때문이다 — 훑기만 해도 요청이 나가면 남의 서버를 두드리게 된다. Enter 로 고른다.

필터·토글(정렬 · 시장 · 연간↔분기 등)은 지금대로 둔다. 화면을 갈아 끼우는 것과
목록을 거르는 것은 다른 물건이라 `Segmented` 안에서 둘을 갈랐다(`kind="group" | "tabs"`).

**목록이 바뀜 것을 소리로 알린다.** 검색어를 넣어도 시장 필터를 눌러도 화면을
읽어 주는 프로그램에게는 아무 일도 안 일어난 것과 같았다. `role="status"` 로
"“반도체” 검색 결과 10건", "시가총액 순 · 전체 · 50종목" 처럼 한 줄씩 말한다.

### 곁가지 — 간헐적으로 깨지던 테스트를 잡았다

3단계를 확인하려고 테스트를 돌리다 **열 번에 다섯 번꾴 아무 테스트나 하나가
깨지는 것**을 봤다. 프론트만 고쳤으니 이번 작업 탓이 아니고, 전부터 그랬던 것이다.

원인은 `conftest.py` 가 이미 적어 둔 그것이었다 — 이 PC 에서는 백신·방화벽이
끚어들어 **이벤트 루프 만드는 것 자체가 가끔 실패**한다. 그래서 세션이 루프 하나를
나눠 쓰도록 만들어 두었는데, **세 곳이 그 약속을 안 지키고 `asyncio.run()` 을 부르고
있었다**(부를 때마다 루프를 새로 만든다). 그 세 곳을 `run_async()` 로 바꾸고,
만들기가 실패하면 잠긐 쉬었다 다시 하도록 했다.

결과: 고치기 전 11회 중 5회 실패 → 고친 뒤 **25회 연속 통과**.

### 확인한 것

키보드만으로 한 바퀴 돌았다 — Tab 이 서는 자리가 순서대로
화면 탭 → 검색창 → 정렬 4 → 시장 3 → 목록표(한 자리) → ☆ → 상세 섹션(한 자리) →
메모창 → 태그. 상단 탭에서 → 를 두 번 눌렀을 때 포커스만 "관심" 으로 가고 선택은
"국내"에 남아 있는 것(`12-focus-tab-keyboard.png`), 표에서 ↓ 로 내려가면 행에 링이
보이고 상세가 따라오는 것(`13-focus-row-keyboard.png`), 상세 섹션에서 → 후 Enter 로
재무가 열리고 주소가 `#/kr/005935/finance` 로 바뀌는 것.

## 4단계 — 일정·분석 화면 정리 ← **다음**

지금까지 손대지 않은 두 화면. **여기서 남은 카드 껍데기 이행이 끝난다.**

### 일정(캘린더) — 425줄, 가장 큰 화면 파일

달력 격자·목록·필터가 한 파일에 있고 카드를 직접 그린다. 쪼개고 `Card`·`Segmented` 로 옮긴다.
달력은 격자 자체가 접근성이 까다롭다 — 날짜 칸을 키보드로 옮길 수 있어야 한다.

### 분석(스크리너)

- 조건 입력이 `<input type=number>` 5개 + `<select>` 인데 **라벨이 11px 이다.** 0단계에서
  "읽어야 하는 문장은 13px 이상, 11px 은 분류 배지에만"이라고 정해 놓고 여기만 예외로 남았다.
- 프리셋 버튼 4개가 `Segmented` 가 아니라 각자 그린 버튼이다. 무엇이 눌려 있는지 표시가 없다.
- 조건을 바꿨을 때 **몇 개가 걸러졌는지**가 눈에 잘 안 띈다. 이 화면의 요점인데.

## 5단계 — 좁은 화면

**지금 이 앱은 노트북 이상에서만 쓸 수 있다.** 화면 폭에 따라 무언가를 감추거나 바꾸는
코드가 저장소에 0곳이다. 좁은 화면에서는 `lg:` 그리드가 풀려 목록 아래로 상세가 내려가고,
표는 `min-w-[720px]` 라 가로로 밀어야 한다.

포트폴리오 링크를 휴대폰으로 열어 볼 사람이 있다면 필요하다. **다만 이건 "안 하면 망가지는"
것이 아니라 범위를 넓히는 일이다** — 2·3·4단계를 마친 뒤 판단한다.

## ✅ 결정된 것 — 주소(URL) (2026-08-31)

라이브러리를 들이지 않고 `lib/useRoute.ts` 로 직접 구현했다. 이 앱의 길찾기는 축이
셋(탭·종목·섹션)뿐이라 라우터가 다루는 중첩 화면·경로 매개변수 같은 개념이 남아돈다.
2단계 항목에 무엇이 어떻게 됐는지 적어 뒀다.

남은 것: 분석(스크리너) 탭이 아직 주소를 안 쓴다. 4단계에서 붙인다.
